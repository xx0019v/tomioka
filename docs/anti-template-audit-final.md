# 反テンプレート監査・実装後評価

> 評価日: 2026-07-22（Asia/Tokyo）
>
> 対象: ホーム画面、調査台帳、章ナビ、キャラクター案内、2D／3D経路図
> 条件: PC 1280×720、mobile 390×844、ローカル本番export、Lighthouse mobile相当

外部事例、公式技術情報、採否、模倣禁止事項は [`external-design-research.md`](./external-design-research.md) に記録した。本書は、その原理を富岡固有の体験へ翻訳して実装し、2回の実画面批評を行った結果である。

## Round 0 — 改修前

### 実画面で確認した主要なテンプレート兆候

1. 大見出し、説明、2CTAを中心にした一般的な没入型LPヒーロー。
2. `eyebrow → 大見出し → 説明`の同じ節構造が後半まで続く。
3. A〜Dの円環ノードが、進行状態と無関係な装飾になっていた。
4. キャラクターが画面端の固定吹き出しとして現れ、help widgetに見える。
5. 円環、浮遊、走査光、グロー、スクロール出現が重なり、意味より常時motionが先に立つ。

該当項目が3件を超えたため、色や影の微調整ではなく、「高級ダークLP」から「街の記憶を綴じる連続調査台帳」へアートディレクションを変更した。

初期評価は **69 / 100**。富岡固有性11 / 15、アートディレクション10 / 15で完成基準未達だった。

## Round 1 — 情報構造と操作の再設計

### 実装

- 装飾円環を、実際の4地点・未採録／採録済み状態・進捗へ接続した操作可能な調査台帳へ置換。
- ホーム全体を序録、手記、手順、巡回、始終、同行の一本の章トレースで接続。
- 各章の英字eyebrowを、記録番号、資料種別、実座標、始点・帰着票など意味のあるメタデータへ変更。
- ホームの固定キャラクターを廃止し、開封後の研究記録内へinline配置。
- ヒーローCanvasを常時描画から、初期化・resize・pointer・設定変更時だけのon-demand描画へ変更。
- 円環回転、浮遊、走査光、ノード点滅、同型スクロールrevealを削減。

### 実画面結果

- PC: 台帳のA〜D切替で地点名、特徴、状態、リンクが同期。装飾だけのノードは残らない。
- mobile: 390×844で横overflowなし。台帳ボタンは58×60px、主要CTAは48px高。
- キャラクター: 閉じた状態も「調査記録の案内を読む」という資料内の横長注釈となり、右下の丸いチャット起点を解消。
- 章リンク: 選択章を`aria-current="location"`で同期し、sticky header下132px／112pxへ正しく停止。

Round 1評価は **86 / 100**。構造と固有性は基準を超えたが、性能、初期layout shift、補助文字contrastに改善余地を残した。

## Round 2 — 性能・アクセシビリティ・最終精度

### 自動監査で発見した問題

- 日本語Webフォントが約568KBのCSSと多数のfont requestを初期発生させていた。
- 開封UIがhydration後に挿入され、CLS 0.167を発生させていた。
- mobileで視覚的に隠した章ラベルが、読み上げ上のリンク名も失っていた。
- 明るい紙面上の資料ラベル、所要時間、アクセス補助文字のcontrastが不足していた。
- hero画像が表示寸法に対して過大だった。

### 修正

- 和文はOS標準の明朝／角ゴシックstackへ切替え、初期CSSを662KBから約95KBへ削減。
- 開封UIをserver/clientで同じ`sealed`状態から描画し、初期layout shiftを解消。
- 章リンクへ明示的な`aria-label`を追加。
- 紙面用と暗色面用の資料ラベル色を分離し、補助文字をWCAG contrastへ調整。
- hero資料画像を800×500 JPEGへ再符号化し、165KBから53KBへ削減。`fetchPriority="high"`を追加。
- mobile見出しを語中で折らない2行構成へ調整し、キャラクター注釈とCTAを同一視線上へ整理。

### 最終Lighthouse（ローカル本番export、mobile emulation）

| 項目 | Round 1 | Round 2 |
| --- | ---: | ---: |
| Performance | 46 | **76** |
| Accessibility | 93 | **100** |
| Best Practices | 100 | **100** |
| SEO | 100 | **100** |
| FCP | 6.2s | **1.9s** |
| LCP | 10.9s | **6.0s** |
| TBT | 300ms | **130ms** |
| CLS | 0.167 | **0** |
| 転送量 | 3,053KiB | **974KiB** |

LCPはローカルHTTP/1.0 server・mobile CPU/network throttleで6.0sであり、継続改善余地として残す。一方、Speed Index 1.9s、TBT 130ms、CLS 0で、初期情報と操作を3D読込で止めない構成は成立している。

## 操作・フォールバック確認

| 確認対象 | 結果 |
| --- | --- |
| 台帳A〜D選択 | pointerで地点名、タグ、状態、リンクが同期。keyboard focusは各native buttonへ到達。 |
| 章移動 | PC／mobileとも該当章へ移動し、現在章表示が同期。sticky UIで見出しを隠さない。 |
| 開封体験 | 開封後にstatusを通知し、キャラクター案内が資料内へ展開。固定global guideはホームで非表示。 |
| WebGL失敗 | `立体表示を利用できないため、二次元の調査図を表示しています`へ遷移し、再試行と全地点リンクを維持。 |
| reduced-motion | CSS全体、開封、台帳、地図、キャラクターに停止／即時切替を実装。3D focusは設定時にanimationを行わない。 |
| mobile 390×844 | 横overflowなし。主要操作48px以上、台帳58×60px、見出しは2行。 |
| 200%相当reflow | 1280px表示の半幅に相当する640×720 CSS viewportで横overflowなし。案内と主要CTAを同時に利用可能。 |
| console | local production画面でerror／warning 0件。 |
| build | ESLint、TypeScript、Next.js static export 18ページすべて成功。 |

## 採用しなかった表現

- 全面WebGL、常時particles、glass、smooth-scroll上書き、WebGL日本語本文。
- GSAP追加。現状の状態遷移はCSS、Canvas、短いrequestAnimationFrameで足りる。
- 参考事例の色、構図、キャラクター、文章、motionの直接模倣。
- 史実、正式な謎、正解の創作。未提供情報は差し替え可能な状態を維持した。

最終判定: **公開可能**。見た目の派手さではなく、街を歩いて記録を綴じる行為そのものが、UI、キャラクター、地図、motionを統一する状態になった。
