# お富ちゃん家 到着・受付 — 6巡ビジュアルQA

検証日: 2026-07-30  
基準ブラウザ: Playwright Chromium / WebKit  
対象: トップページ `#access`

## 第1巡 — 390×844 / 情報の順序

- 画像: `round-1-390.png`
- 着眼点: 最初の視線が「物語の入口」→現地写真→住所へ進むか。
- 問題: 旧実装は住所・アクセス・時間・駐車場が同じ強さで並び、開始地点の現物を確認できなかった。
- 修正: 現地写真を主役にし、住所を受付票の先頭へ移動。徒歩時間・受付時間・参加条件を従属情報にした。
- 差分: 等幅の情報グリッドから、写真と到着票による一方向の読み順へ変更。
- 判定: PASS。横スクロール0、CTA折返し0、最小操作高48px。

## 第2巡 — 320×844 / 下限幅

- 画像: `round-2-320.png`
- 着眼点: 見出し、住所、時刻、CTAが不自然に分断されないか。
- 問題: 320pxでは長い見出しと住所が最も破綻しやすい。
- 修正: 見出しを意味単位の2行に固定し、住所・時刻・参加条件を一単位で保持。左右余白を16pxへ調整。
- 差分: 助詞だけの孤立、単位の孤立、ボタンの2行化を防止。
- 判定: PASS。文書幅320px、横超過0、主要CTA52px、住所コピー48px。

## 第3巡 — 430×844 / 大型モバイル

- 画像: `round-3-430.png`
- 着眼点: 余白が間延びせず、片手で行動へ到達できるか。
- 問題: 幅が増えると単純な中央寄せカードはテンプレート感が強くなる。
- 修正: 紙面の罫線、到着印、写真キャプション、縦の道順を別々の密度で配置。
- 差分: 同じ角丸カードの反復を使わず、一枚の到着票として連続させた。
- 判定: PASS。横超過0、全リンク1行、操作対象48px以上。

## 第4巡 — 768×900 / タブレット切替

- 画像: `round-4-768.png`
- 着眼点: 2列化の境界で写真・住所・案内が窮屈にならないか。
- 問題: 単純な2列化では右列の住所と参加条件が詰まりやすい。
- 修正: 写真を2段分占有させ、受付票ときぬ案内を縦に分け、道順とCTAを全幅へ戻した。
- 差分: コンテンツの意味に合わせて列をまたぐ非対称グリッドへ変更。
- 判定: PASS。横超過0、情報欠落0。

## 第5巡 — 1024×900 / 中型デスクトップ

- 画像: `round-5-1024.png`
- 着眼点: 写真と受付票の力関係、道順の接続。
- 問題: 横幅だけを広げると空白が均一になり、情報同士の関係が弱くなる。
- 修正: 写真を左、到着印付き受付票を右へ置き、一本の道順を両列の下に横断させた。
- 差分: 空白を「写真の余韻」と「次の行動の間」に使い分けた。
- 判定: PASS。CTA3本が1行、道順4段階が連続。

## 第6巡 — 1440×900 / 公開構図

- 画像: `round-6-1440.png`
- 着眼点: 大画面で密度が散らず、一つの視覚主題に見えるか。
- 問題: 旧実装は大画面でも単純な2列アクセス欄に留まった。
- 修正: 見出しを左へずらし、写真・受付票・きぬ・横断ルートを一枚の記録紙上に構成。
- 差分: 「アクセス情報」から「到着の場面」へ役割を変更。
- 判定: PASS。最大内容幅を保持し、写真・本文・行動の優先順位を確認。

## モーション・操作

- 専用E2E: Chromium 3件 + WebKit 3件、計6件合格。
- 両ブラウザ: 9幅すべて横超過0、リンク折返し0、操作高48px以上。
- 通常時: 受付セクション内の反復は「きぬ」の呼吸1本。まばたきは3.5〜8秒の不規則な一回動作。
- 画面外／非表示タブ: `data-active=false` となり反復停止。
- reduced motion: `data-active=false`、登場要素opacity 1、受付内の稼働アニメーション0、横超過0。
- きぬのタップ: 4案内を巡回、220msの連打ガードを確認。
- Googleマップのフォーカス／ポインターダウン: 地図案内へ反応。
- 住所コピー: 成功／失敗の状態文を `role=status` で通知。

## 注記

全セクション画像ではサイト共通の固定ヘッダー・下部ナビが画像上に重なる。通常の844pxビューポートではスクロールに伴い内容が移動し、個々の操作対象を覆い続けないことを別途確認した。
