# お富ちゃん家「到着・受付」再設計方針

## 目的

トップページのアクセス欄を、住所の羅列から「富岡に着き、受付を見つけ、街へ出る」ためのデジタル受付へ変える。屋外で片手操作しても、開始地点・徒歩時間・受付時間・参加条件・次の行動を迷わず判断できることを最優先にする。

## 体験の一文

古い旅券のような一枚の到着票に、現地写真、絹糸でつないだ道順、受付係の「きぬ」が同居し、物語と実用情報が同時に立ち上がる。

## 情報と構図

1. 「物語の入口は、お富ちゃん家」を意味のまとまりで改行する。
2. 現地写真と正式名称を最初の確認材料にする。
3. 住所を主情報、駅からの徒歩時間と受付時間を次点にする。
4. 無料・事前申込不要を一つの参加条件として示す。
5. 「上州富岡駅 → 富岡の街 → お富ちゃん家 → 物語の入口」を順序付きリストにする。
6. Google マップ、街歩きマップ、開催情報の順に行動を置く。

主題は「旅の終点ではなく、物語の出発印」。承認済みの現地写真、紙、赤煉瓦、桑の葉、一本の絹糸で構成する。温かい紙色を面、深緑を文字、赤煉瓦色を唯一の能動アクセントにする。モバイルは写真→受付票→道順→行動、デスクトップは写真と受付票を非対称に重ね、道順を横断させる。等幅カードの反復、意味のない小円、発光グラデーション、過剰な英語ラベル、装飾だけの3Dは避ける。

## 日本語組版

助詞・約物・単位が孤立しないよう、見出しと短い事実は意味単位の `span` で固定する。住所、日付、時刻、徒歩約5分、無料、事前申込不要は一つの情報単位として扱う。本文は `word-break: normal`、`line-break: strict`、`overflow-wrap: anywhere` を基本にし、ボタンラベルは320pxでも折り返さない。

## インタラクションとモーション

セクションが画面に入ると、写真、受付票、道順が一度だけ順に現れる。「きぬ」に触れると4つの短い案内を順番に返し、220ms以内の連打は無視する。Google マップへのフォーカス／ポインターダウン時は入口方向を案内する。住所コピーは成功・失敗を `role="status"` で通知する。

CSS transitions / keyframes と IntersectionObserver を採用する。既存依存にない GSAP、ScrollTrigger、Lenis、React Bits、Three.js、Vanta、独自 shader は追加しない。今回の表現は一回の登場と小さなキャラクター反応で成立し、スクロール補間や GPU 描画を導入する理由がないためである。

通常時の常時ループは、画面内にいる「きぬ」の呼吸と不規則なまばたきの最大2本。画面外・非表示タブでは停止し、`prefers-reduced-motion: reduce` では最終状態に固定して全ループを0本にする。

## レスポンシブ・公開基準

- 基準: 390×844、下限: 320px
- 検証幅: 320 / 360 / 375 / 390 / 393 / 430 / 768 / 1024 / 1440
- モバイルの操作対象は48px以上、本文は16pxを下回らない。
- `section`、見出し、`figure`、`address`、`dl`、`ol` を意味どおりに使う。
- 写真には識別できる代替テキスト、装飾線には `aria-hidden` を付ける。
- 横スクロール0、ボタン折返し0、不自然な助詞孤立0、reduced motion時の稼働アニメーション0、コンソールエラー0を公開条件とする。
